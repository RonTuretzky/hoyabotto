The whole journey

Estimated hands-on time is about two working days plus printing. Print first; everything else can overlap.

0 · Set up the Mac (do this today, anywhere)

Get the code and the tools

≈ 20 min

Everything runs from one folder on the Mac. uv makes the Python environment in seconds; the tests prove the install before any hardware is involved.

  1. Install uv and Python 3.12 (brew install uv python@3.12).
  2. Clone the repo and create the environment:
    git clone https://github.com/RonTuretzky/xlerobot-farm.git
cd xlerobot-farm/software
uv venv --python 3.12 .venv && . .venv/bin/activate
uv pip install -e .
python -m pytest -q          # expect: 70 passed
  3. Run the whole program on fakes and open the viewer:
    farm sim --auto-answer
# in a browser: http://localhost:8765
  4. You should see two POURED cycles and the viewer with frames, questions and the STOP button.
You need
  • MacBook (the Neo)
  • internet
Links
  • Software README
  • uv install
Done when

pytest passed and farm sim showed two POURED cycles

Watch out

If pytest cannot import lerobot, the venv is not active: run . .venv/bin/activate first.

Log in to the model backends

≈ 15 min

Vision (looking at trays, teaching poses) runs on your Claude subscription through the claude command line. Jev and Astra run through OpenRouter.

  1. Install and log in to Claude Code: quickstart, then run claude once and complete /login. Test headless: 
    claude -p "reply with the JSON {\"ok\": true}" --output-format json
  2. Rotate the OpenRouter key (it was pasted in chat) at openrouter.ai/settings/keys, put a small credit limit on it, then:
    cp .env.example .env
# edit .env: OPENROUTER_API_KEY=sk-or-v1-…
  3. Check both from the farm:
    farm review -p sim      # Astra proposal from the simulator’s evidence (uses OpenRouter)
You need

  • OpenRouter account with a few dollars

claude -p returned JSON and farm review printed a proposal

Optional: questions on your phone (Telegram)

≈ 15 min

The viewer works on the same Wi-Fi. Telegram lets the robot ask you anywhere: one message with buttons, your tap is the authorization record.

  1. Message @BotFather: /newbot, copy the token.
  2. Send your new bot any message, then open https://api.telegram.org/bot<TOKEN>/getUpdates and copy your chat id.
  3. Add to .env:
    TELEGRAM_BOT_TOKEN=123456:ABC…
TELEGRAM_CHAT_IDS=987654321
  4. From now on every question goes to the viewer and Telegram; the first answer wins.
You need

bot token and chat id in .env

Only the chat ids listed can answer; anything else is ignored and logged.

Install a slicer for the AnkerMake M5C

≈ 15 min

The M5C accepts G-code from AnkerMake Studio, PrusaSlicer or Cura. You only need one; AnkerMake Studio has the printer profile built in and sends jobs over Wi-Fi.

  1. Install AnkerMake Studio (or PrusaSlicer with the M5C profile) and pair the printer.
  2. Default profile for every part: 0.2 mm layers, 3 walls, 20 % infill, PLA 210–220 °C, bed 50–60 °C, no supports.
  3. Never run the Prusa MINI G-code from the modular-table download on the M5C: it is sliced for another machine.
You need
  • AnkerMake M5C on the same Wi-Fi
  • 1.5 kg PLA (two spools) if you print the table, 0.5 kg without
Links
  • AnkerMake downloads
  • M5C specs (Fabbaloo)
Done when

slicer installed and printer paired

Watch out

The 0.4 mm nozzle kit for the M5C is a different part from the K1 Max kit.

1 · Print the parts (start the printer, then keep going)

Print in this order

≈ 5 min

Trays first (they gate the growing), then the nests (they gate the robot), then the small parts. The table is optional and long; start it last or skip it.

  1. Queue: cress planter (6 pieces) → nest A → nest B → paddle + bottle rest + tags on one plate → table (optional).
  2. Download: planter STLs · nest_cress.stl (print twice) · paddle · bottle rest · tag id1 · tag id2.
  3. Tag tiles: pause at Z = 1.0 mm and switch to black filament for the raised cells, or colour the raised cells with a black marker afterwards.
You need
  • M5C
  • PLA
Links
  • Parts README (assumptions to verify)
  • Printing page
Done when

planter, two nests, paddle, rest and tags printed

Watch out

The square germination kit’s 220 mm tray does not fit the M5C; skip it or print it at 95 %.

Decide about the table (and what it costs)

≈ 10 min

The robot needs the trays at a repeatable height within reach; it does not need a printed table. The chosen modular table works but is ~45 h of printing.

  1. Fast path: any stable surface at the right height (a box, a shelf, a cheap side table) with the nest plates screwed or taped to it. Zero print time.
  2. Printed path: Modular Table (100 % printed), CC0. The creator’s table is 63 h / 909 g on a Prusa MINI; on the M5C expect ≈ 40–45 h and 0.9–1.2 kg for a top big enough for two nests (≈ 5 × 3 tiles). All parts fit the 220 mm bed.
  3. The 13 editable .3mf files are downloaded (mirror) and all fit the M5C bed; slice them yourself for the M5C. The other ZIP holds Prusa MINI G-code only: never send it to the M5C.
  4. Height: measure from the floor to the robot’s shoulders on the cart, subtract 5–10 cm: that is the tray-rim height you want.
You need
  • a decision
Links
  • Modular table files
Done when

table decided: surface chosen or table printing

Watch out

Pre-sliced per-part times from the download: 4 legs 7h48m (452 g), 8 connectors 3h19m (384 g), tops 1.4–2.3 h each — those are MINI times.

Check each print before trusting it

≈ 15 min

A nest that is 1 mm tight or a rest that is 1 mm loose costs a whole teaching session later.

  1. Nest: the trough drops in and lifts out freely; the tag tile sits flush in its recess; the spout notch faces where the bottle will come from.
  2. Paddle: the BH1750 board fits its pocket; the handle grooves face the gripper.
  3. Bottle rest: your bottle drops in and stands vertical; if it wobbles, reprint with a smaller bore (edit make_parts.py).
  4. Planter: rinse, fill the trough, leave it on paper for 30 min: no wet patch underneath.
You need
  • printed parts
  • the real bottle
  • BH1750 board
Links
  • Growing page: leak test
Done when

all fits checked, no leaks

2 · Electronics: the light sensor

Flash the ESP32

≈ 30 min

The ESP32 reads the light sensor and prints JSON over USB. Flashing is a one-time step with the Arduino IDE.

  1. Install the Arduino IDE, then add the ESP32 boards: Settings → Additional boards manager URLs → https://raw.githubusercontent.com/espressif/arduino-esp32/gh-pages/package_esp32_index.json → Boards Manager → install “esp32”.
  2. If the board does not show a serial port on macOS, install the CP210x or CH34x driver (check which chip your ELEGOO board has).
  3. Open software/firmware/esp32_light/esp32_light.ino, board “ESP32 Dev Module”, choose the port, Upload.
  4. Watch it: 
    farm light-monitor            # one line per second: lux, status, seq
You need
  • ELEGOO ESP32
  • USB data cable
  • Arduino IDE
Links
  • Arduino-ESP32 install
  • Firmware source
Done when

light-monitor shows lux changing when you cover the sensor

Watch out

A charge-only USB cable shows nothing. The cable from the cart must be a data cable.

Wire the BH1750 and mount it on the paddle

≈ 45 min

Four wires. Get them right once and the sensor is a status-bearing reading for the rest of the project.

  1. Solder the header pins onto the BH1750 if they came loose.
  2. Wire per the diagram (3V3, GND, GPIO21 → SDA, GPIO22 → SCL). Use the flexible 22 AWG wire; leave a service loop at the wrist.
  3. Screw the board into the paddle pocket, sensor face up; route the cable down the handle groove.
  4. Confirm again with farm light-monitor: cover / uncover the paddle.
You need
  • BH1750
  • flexible wire
  • soldering iron (buy in Japan)
  • printed paddle
Links
  • Hardware page
  • BH1750 datasheet
Done when

paddle wired, readings valid while the cable is flexed

Watch out

Lux is not PPFD; the number is for comparing days, never for deciding water.

3 · Assemble the robot (Sep 30)

Assemble the robot

≈ 240 min

The WowRobo two-wheel Combo arrives mostly assembled. Follow the vendor video for brackets and screws; our assembly page tracks integration checkpoints.

  1. Work through assembly steps 1–4 (lay out, cart + drive base, arms + head, cabling) with the WowRobo 0.4.0 (two-wheel) assembly video. First confirm the kit: two large drive wheels + casters = 0.4.0 (this video); three omni wheels = 0.3.0 (older video), and tell me, because the software profile assumes the two-wheel motor map.
  2. Power: use the two supplied 12 V/8 A wall adapters; check the labels accept 100 V (Japan). Battery stays out.
  3. Plug into the powered hub: 2 motor boards, 3 cameras, ESP32. Hub → Mac USB-3 port. Mac on its charger.
You need

  • IKEA cart
  • powered hub
  • hex keys

robot assembled, all USB devices on the hub, motors powered from wall adapters

Give the loose servos their IDs (the “FD” step in the video)

≈ 20 min

At the start of the vendor video they use Feetech’s Windows program “FD” to type an ID into each loose servo. Every servo on a chain needs a unique ID: the arms come numbered 1–6, the two head servos must be 7 and 8, the two wheel servos 9 and 10. On the Mac the farm command does the same thing through the same motor board.

  1. Do this before the servos are mounted and chained. Plug ONE motor board into the Mac (USB) and its 12 V supply, and connect exactly ONE loose servo to it.
  2. Run the command for that servo, press ENTER when prompted, then label the servo with its number:
    cd software && . .venv/bin/activate
farm set-motor-id --name head_motor_1        # → ID 7
farm set-motor-id --name head_motor_2        # → ID 8
farm set-motor-id --name base_left_wheel     # → ID 9
farm set-motor-id --name base_right_wheel    # → ID 10
  3. Swap the servo between commands: only one servo on the board each time. If a servo already reports the right ID (some kits ship pre-numbered), the command simply confirms it.
  4. Later, farm devices --probe must show IDs 1–8 on one board (left arm + head) and 1–6, 9, 10 on the other (right arm + wheels).
You need
  • one motor board + its 12 V supply
  • the four loose servos (2 head, 2 wheel)
  • a marker for labels
Links
  • Vendor video (0.4.0), first minutes
  • LeRobot: configure motors
Done when

four servos labelled 7, 8, 9, 10

Watch out

Two servos with the same ID on one chain both go silent. Never set IDs with more than one servo connected.

4 · Bring the robot up on the Mac

Find the ports and cameras

≈ 15 min

The profile must name the two motor buses and the three cameras by identity. The probe pings each bus and snapshots each camera so you do not guess.

  1. cd software && . .venv/bin/activate
farm devices --probe
  2. The probe reports which port answers motor IDs 1–8 (bus 1: left arm + head) and which answers 9–10 (bus 2: right arm + wheels). Snapshots land in data/devices/; open them and decide which index is head, left wrist, right wrist.
  3. Edit profiles/paper-tray-v0.yaml: robot.port1, robot.port2, and index_or_path for each camera.
You need
  • assembled robot
Links
  • Profile file
Done when

profile has both ports and three camera indices

Watch out

macOS asks for camera permission the first time; allow it for Terminal.

Calibrate the joints once

≈ 20 min

LeRobot needs each servo’s range once. This is the one setup step where a person moves the arms by hand — it is not operation.

  1. farm calibrate
  2. Follow the prompts: move the left arm + head to mid-range, ENTER; sweep every joint through its full range, ENTER; same for the right arm.
  3. The file lands in ~/.cache/huggingface/lerobot/calibration/robots/xlerobot_2wheels/; back it up.
You need
  • both arms supported
  • motor power on
Links
  • LeRobot calibration docs
Done when

calibration file saved

Watch out

If a joint is skipped the model will later push it toward an impossible target and the safety clamp will stop everything.

Prove every device with one command

≈ 10 min

Before any motion the program connects everything and asks the vision model to confirm which camera is which. A swapped camera is caught here, not over a tray.

  1. farm check
  2. Expect: problems: none, joints OK, health OK, three cameras OK, light OK, views: {"status": "OK", …}.
  3. If views says INVALID, two camera indices are swapped: fix the profile and re-run.
Done when

farm check is all OK

Watch out

Startup also marks any action that was ATTEMPTED before a crash as UNKNOWN and asks you to reconcile it in the viewer.

5 · Build the station

Lay out the station

≈ 60 min

The program assumes nothing moves: trays in nests, bottle in its rest, paddle in its rest, cart parked. Everything the model teaches is relative to this layout.

  1. Place the surface so the tray rims are 5–10 cm below the arm shoulders and 15–30 cm in front of them (see diagram).
  2. Screw or tape both nest plates down; drop a tag tile in each recess; set the cress planter into nest B (and A when you have two).
  3. Bottle rest on the right side within the right arm’s reach; paddle rest on the left. Tape them. Cart brakes on.
  4. Fill the bottle only half for the first days. A spout that pours a thin stream matters more than the bottle: the Nalgene needs a fitted spout or use a small squeeze bottle.
You need
  • nests, rests, tags
  • planter with paper and water
  • bottle with a spout
  • tape / screws
Links
  • Growing page
  • Prints page: nests
Done when

nothing on the station can move; bottle and paddle in their rests

Watch out

Direct sunlight on the wrist camera makes every judgement UNKNOWN. Shade the station.

Sow the first tray

≈ 20 min

Cress on household paper: germinates in 2–4 days, so the robot has something to look at within the trip.

  1. Follow the setup steps: leak test, wick contact, sow a small even patch, keep an unseeded paper edge visible near the refill opening (the model judges wetness there).
  2. Log it in the notebook.
You need
  • cress seed (buy locally)
  • kitchen paper
  • water
Done when

tray sown, paper edge visible

Watch out

Do not carry seed or soil through customs; buy locally.

6 · Let the model teach the robot

Let the model teach every pose

≈ 60 min

Nobody drives the arm. For each needed pose the vision model looks through the wrist and head cameras, moves in small clamped steps and saves the joints as a keyframe when the goal is visibly met.

  1. farm teach-all
  2. Watch the viewer (and stand near the STOP button). Each pose prints OK or FAILED with the model’s reason and cost.
  3. Poses learned: bottle rest above/grip, bottle upright, paddle rest above/grip, and per tray: look, pour, measure.
  4. Redo a single pose:
    farm teach --arm right --goal "spout 3 cm above the refill opening of tray B" --save pour_B
You need
  • station laid out
  • bottle and paddle in rests
Links
  • LLM-servo source
Done when

teach-all reports failed: none

Watch out

If the model aborts with “target not visible”, fix the lighting or the head pose first; it is telling the truth.

7 · Water for the first time

Rehearse with an empty bottle

≈ 20 min

The first full cycle must be dry: it proves pick, approach, tilt, upright and park without a drop of water.

  1. Empty the bottle. Run:
    farm once --tray B
  2. The viewer asks “Authorize one pour?” — type your name, press authorize one pour. Watch the arm pick, approach, tilt, return upright, verify, park.
  3. Repeat until it is boring. Ten clean runs is the gate.
Done when

10 clean empty-bottle cycles

Watch out

Press STOP in the viewer if anything looks wrong; motors hold instantly and only a named person can clear it.

Measure a real pour into a cup

≈ 15 min

A tilt for N seconds is not a volume until you measure it. The cup test records the millilitres so every later pour is a known dose.

  1. farm cup-test --tilt 25 --seconds 1.5 --who yourname
  2. Hold a kitchen measure under the spout when prompted, read the millilitres, type them. Repeat with a fuller bottle; the last measurement is the calibration.
You need
  • kitchen measuring cup
  • half-full bottle
Done when

pour calibration saved (data/pour_calibration.yaml)

Watch out

Aim for 20–30 mL per pour: enough to wet the reserve, never enough to flood the paper.

The first real cycle

≈ 20 min

Now water goes into the tray. Rules, Jev and you all have to agree.

  1. farm once --tray B
  2. Authorize in the viewer. After the pour the model verifies: water visible / paper edge damp / spill CLEAR. If it cannot see the rim, the cycle pauses with delivery UNKNOWN and asks you to look.
  3. Open the cycle record in the viewer: every observation, decision and action with its status.
Done when

first POURED cycle with a VERIFIED pour

Watch out

A pour that ends UNKNOWN blocks every later cycle until you reconcile it. That is by design.

8 · Run it every day

Run hourly

≈ 5 min

The care loop runs on a schedule, rests the arms between cycles (torque off so servos cool), and reconnects if a USB device hiccups.

  1. farm run --every 3600
  2. Viewer: http://<mac-ip>:8765 from your phone on the same Wi-Fi (or Telegram). Leave the Mac on its charger with sleep disabled.
Done when

farm run has completed a day of cycles

Watch out

Keep the Mac awake: System Settings → Battery → prevent sleep on power, or run caffeinate -i farm run --every 3600.

Let Jev earn authority

≈ 5 min

Jev starts in shadow. After ten cycles where its route agreed with the rules and with you, it is promoted to route; after ten more agreeing pour decisions, to approve — it then authorizes routine pours and just notifies you.

  1. Nothing to do: promotion is automatic and recorded as events. Watch the Authority panel in the viewer.
  2. Demote at any time with the buttons; a spill at reconciliation demotes automatically.

Jev reached route

≈ 10 min

Once a day Astra reads the evidence and proposes one change. You accept or reject in the viewer. The database is backed up every day.

  1. farm review

Turn the robot’s own runs into a learned pour (v2)

≈ 90 min

Keyframes replay one pose; a learned policy re-aligns the grasp and spout from the cameras when the bottle sits slightly differently. The training data is the robot’s own successful runs — nobody demonstrates.

  1. Record while running (each cycle becomes an episode with 30 fps frames + joint targets):
    farm run --every 3600 --record        # writes data/dataset (LeRobotDataset v3, .pos joint names, 3 cameras)
  2. Target 60–100 saved episodes (30–50 per tray); failed cycles are discarded automatically.
  3. Train locally (ACT, Apple-silicon GPU) or on a rented GPU (SmolVLA base, pretrained on SO-100/101 data):
    python -m farm.learning.train --policy act --dataset-root data/dataset --steps 20000 --device mps
# or: python -m farm.learning.train --policy smolvla --dataset-root data/dataset --steps 20000 --job-target a10g-small
  4. Evaluate offline against held-out episodes, then run the checkpoint as a skill on the simulator and, with the STOP button in reach, on the robot:
    python -m farm.learning.evaluate --checkpoint data-train/act_farm/checkpoints/last/pretrained_model --dataset-root data/dataset
farm policy-test --checkpoint data-train/act_farm/checkpoints/last/pretrained_model        # simulator
farm policy-test --checkpoint … --real --steps 100                                           # robot, clamped, e-stop ready
  5. Only when it beats the keyframe skill on held-out episodes: set policy.enabled: true (shadow first) in the profile.
You need
  • 60–100 recorded episodes
  • Mac (ACT) or a rented GPU (SmolVLA)
Links
  • Research: data and policies that exist
  • Best same-arm pour data (100 ep)
  • SmolVLA base
Done when

a checkpoint exists and farm policy-test ran it on the simulator

Watch out

Already done once as a pipeline check (Sep 27): ACT on 35 public SO-101 bottle-pour episodes, 5000 steps in ~70 min on the Mac, loss 3.3 → 0.42, checkpoint drove the simulator. That checkpoint is a motion prior for someone else’s table: the last 10–20 cm to our tray only comes from our own episodes. An offline error is not a success rate.

9 · Grow, review, hand over

Daily plant checks

The robot inspects and waters; a person still looks at the crop once a day and writes two lines. The photos are in the viewer.

  1. Follow the daily plan: paper evenly damp, no puddles, cover off once shoots stand, bright light.
  2. Log observations in the notebook; note every manual top-up as an intervention.
